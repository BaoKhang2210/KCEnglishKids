Three-layer leaf module organized per resource (Topic / Lesson / Activity):
- `src/routes/*Routes.js` — thin Express routers mounting GET endpoints (`/:id`, `/:id/activities`, `/curriculum-path`) and attaching the `optionalProtect` middleware from `../middlewares/authMiddleware` where user context is optional.
- `src/controllers/*Controller.js` — async handlers that read from `../models`, populate related docs via Mongoose `.populate()`, merge child progress from `Progress` / `ActivityResult`, and return a uniform `{ success, data }` JSON envelope; errors are forwarded to `next(error)` for centralized error handling.
- `src/models/*.js` — Mongoose schemas defining the domain: `Activity` (question/options schema with `activityType` enum), `Lesson` (linked to `Topic`, `CurriculumUnit`, `Vocabulary`, `LanguageContent`), `Topic` (slug-based lookup, age-group filtering), plus two session-scoped models: `ClassroomSession` (teacher-led, Kahoot-like per-question results) and `LearningSession` (child self-paced lesson run).
Dependency direction is strictly routes → controllers → models; controllers never import each other. Cross-resource reads (e.g. lesson controller querying `Activity`, `Vocabulary`, `CurriculumUnit`, `Progress`, `ActivityResult`) happen at query time rather than through an application service layer.
