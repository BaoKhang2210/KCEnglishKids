Three-layer MVC split under `src/`:
- Routes (`routes/progressRoutes.js`, `routes/learningRoutes.js`) are thin Express routers exposing `/api/children/:id/progress`, `/api/learning/sessions`, and `/api/learning/activity-results`; they apply the shared `optionalProtect` auth middleware so both logged-in CHILD users and admin callers can reach them.
- Controllers (`controllers/progressController.js`, `controllers/learningController.js`) validate request bodies/params, resolve the effective child id (preferring `req.user._id` when role is `CHILD`), then delegate business logic to services or query models directly. The progress controller aggregates per-child stats (total stars, completed lessons, weak vocabulary) by populating `Progress`, `Topic`, `Lesson`, and `Vocabulary` refs.
- Service layer (`services/learningService.js) encapsulates domain rules: `getOrCreateSession` finds or creates an in-progress `LearningSession`, and `processActivityResult` evaluates answers against the `Activity` schema, persists an `ActivityResult`, updates session totals/status, upserts a `Progress` record (with unique `{child, lesson}` index), accumulates weak vocabulary with `mistakeCount`, and returns the next activity in the lesson.
- Models (`models/Progress.js`, `models/ActivityResult.js`) define Mongoose schemas with references to `User`, `Topic`, `Lesson`, `Activity`, `Vocabulary`, and `LearningSession`, plus composite indexes for efficient child-scoped queries.
Dependency direction is strictly routes → controllers → services → models; controllers never import models except where the progress endpoint needs direct aggregation.
