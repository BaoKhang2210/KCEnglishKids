Single-page React application bootstrapped via Vite (`vite.config.ts`), split into two user-role frontends under one codebase:
- Routing: `src/App.tsx` declares all routes under `/` (child) and `/teacher/*` (teacher), guarded by `ProtectedChildRoute` / `ProtectedTeacherRoute` wrappers that check `user.role` from `AuthContext`.
- Auth state: `src/context/AuthContext.tsx` is the single source of truth — it persists `kc_token`/`kc_user` in `localStorage`, hydrates on mount via `authApi.getMe()`, and exposes login/register/logout plus `setAgeGroup`.
- API layer: `src/services/api.ts` centralizes every HTTP call behind typed client modules (`authApi`, `topicsApi`, `lessonsApi`, `activitiesApi`, `learningApi`, `adminApi`, `teacherApi`, `classroomSessionApi`, `vocabMasteryApi`, `parentNotificationApi`) built on a small `api.{get|post|patch|put|delete}` wrapper that injects the Bearer token from `localStorage`. A dev proxy forwards `/api` to `http://localhost:5000`.
- Domain layers: `src/pages/child/*` are route-level pages; `src/components/child/*` are reusable UI pieces; `src/components/child/games/*` each implement one activity engine as a self-contained component consuming `ActivityQuestion`/`ActivityOption` types from `src/types/index.ts`; `src/dashboards/teacher/*` compose the teacher workspace layout and CRUD screens.
- Shared data: `src/data/badges.ts` and `src/data/stickers.ts` provide static game assets; `src/utils/audio.ts` wraps Howler for SFX and TTS; `src/services/vocabMasteryService.ts` batches vocabulary-mastery records and syncs them after auth.
- Styling: Tailwind CSS v4 via `@tailwindcss/vite` plugin, with `clsx` + `tailwind-merge` for conditional class composition.
- Types: `src/types/index.ts` defines the canonical domain model (`User`, `Topic`, `Lesson`, `Activity`, `ClassroomSession`, `VocabularyMasteryRecord`, etc.) consumed uniformly across services and components.
